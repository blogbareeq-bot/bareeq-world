# Bareeq World v4.18.2

> إصدار استبدال كامل: Gemini 3.1 Flash TTS Preview بصوت Sadaltager الواحد لجميع المقالات، مع توليد متسلسل، حماية 429، استكمال تدريجي، وكاش إنتاجي يعيد استخدام التسجيلات المكتملة.

# عالم بريق — V4.18.2 Full Sadaltager Rollout

نسخة إطلاق كاملة من **عالم بريق — نافذتك إلى المعرفة**، مبنية بـAstro ومهيأة للنشر من GitHub إلى Cloudflare Pages.

## الحكم

عند ضبط `BAREEQ_TTS_PROVIDER=gemini` وإضافة `GEMINI_API_KEY` كـProduction Secret في Cloudflare، يستهدف البناء **كل المقالات المنشورة** بصوت **Sadaltager** الواحد عبر `gemini-3.1-flash-tts-preview`.

المولد يرسل طلبًا واحدًا في كل مرة، بفاصل افتراضي 9 ثوانٍ، ويعيد محاولة 429/5xx حتى 8 مرات مع احترام `Retry-After` و`retryDelay`. إذا استمر 429 أو اقتربت مرحلة التوليد من ميزانيتها الزمنية الافتراضية (13 دقيقة)، لا يهدم ذلك النشر: المقالات التي اكتملت بـSadaltager تبقى جاهزة، بينما يحتفظ الباقي مؤقتًا بتسجيل Cedar/Hamed المعتمد، ثم يُستكمل الناقص في نشر لاحق من دون إعادة توليد ما تم نشره بالفعل.

يبقى `BAREEQ_TTS_PROVIDER=bundled` مسار رجوع فوري لا يستهلك أي طلبات توليد، ويحافظ على Cedar/Hamed المقفلين داخل المستودع.

## تحديث V4.18.2 — Sadaltager لجميع المقالات

- إلغاء قيد «مقال تجريبي واحد»؛ خطة Gemini الآن تشمل **11 مقالًا / 70 طلبًا / 80,664 حرفًا مصدريًا** قبل احتساب الكاش الحي.
- تثبيت **Sadaltager فقط** في مسار Gemini؛ لا توجد بنية تشغيلية لصوت Gemini ثانٍ.
- رفع الفاصل الافتراضي بين بدايات الطلبات إلى `9000ms`، مع بقاء التنفيذ متسلسلًا بالكامل.
- رفع إعادة المحاولة الافتراضية إلى 8، مع قراءة `Retry-After` (بما في ذلك القيم الكسرية) و`retryDelay` من رد Google، ثم Exponential Backoff + Jitter عند الحاجة.
- إضافة سقف أمان `80` طلبًا جديدًا في البناء الواحد، وميزانية توليد `780000ms` لحماية زمن بناء Cloudflare.
- عند استمرار 429 أو انتهاء ميزانية التوليد، يتحول البناء إلى **Progressive Fallback** بدل الفشل: ما اكتمل ينشر بـSadaltager، والباقي يحتفظ بـCedar/Hamed حتى النشر التالي.
- قبل أي طلب جديد، يحاول البناء استعادة تسجيل Sadaltager غير المتغير من `https://bareeqworld.com`؛ لذلك المقال التجريبي المنشور سابقًا، وأي مقال يُستكمل لاحقًا، لا يحتاج إعادة توليد طالما بقي النص والإعدادات متطابقة.
- الإبقاء على `GENERATOR_VERSION=8` عمدًا لأن عقد الملف الصوتي والأسلوب والبصمة لم تتغير؛ هذا يسمح بإعادة استخدام تسجيل Sadaltager الصحيح المنشور سابقًا بدل إبطاله بلا داعٍ.
- الحفاظ على التزامن، التقديم والرجوع، السرعات، حفظ موضع الاستماع 30 يومًا، واجهة الجوال/التابلت، وCedar/Hamed كرجوع فوري.

### أوامر المرحلة الثانية

```bash
# مجاني ولا يتصل بأي مزود
npm run voice:lab:plan

# عرض الأصوات المتاحة بعد إضافة مفتاح المزود محليًا
npm run voice:lab:voices -- --provider=elevenlabs
npm run voice:lab:voices -- --provider=munsit

# توليد صريح بعد مراجعة الخطة؛ الحد الافتراضي دولاران
npm run voice:lab:generate -- --all-enabled --max-usd=2

# بناء المقارنة العمياء وفحصها بعد اكتمال المرشحين
npm run voice:lab:build
npm run voice:lab:check
npm run voice:lab:serve
```

انسخ `.env.voice-lab.example` إلى `.env.voice-lab` محليًا ثم أضف المفاتيح هناك فقط. لا تضف الملف إلى Git ولا ترسل محتواه في المحادثة.

- روابط Blogger الثمانية القديمة تعمل؛ سبعة منها إلى المقالات الحالية وواحد إلى «ابدأ من هنا»، مع تحويل خلاصة Blogger إلى `/rss.xml`.
- تنظيف `dist/` قبل كل بناء لمنع بقاء ملفات إصدار قديم ذات أسماء مموهة.
- تحميل مسبق متجاوب لصورة البطل عبر `imagesrcset` و`imagesizes`.

## بنية الواجهة

- عرض تحريري ممتد حتى 1920px مع هامش آمن، وعرض قراءة مريح للمقال.
- رأس مستلهم من نسخة Blogger السابقة، وشريط أحدث المقالات، وخمسة أقسام فقط في الأعلى.
- لا يظهر «الكل» في شريط الأقسام، ولا يتكرر تنقل الأقسام في وسط الرئيسية أو التذييل.
- Mega Menu على سطح المكتب وAccordion داخل درج الجوال.
- تذييل جوال أحادي العمود وقابل للطي، وبريد إلكتروني باتجاه LTR وألوان نص موحدة.
- وضع داكن بتباين AA مختبر، وخطوط عربية ذاتية الاستضافة.

| Root directory | فارغ |

### متغيرات القراءة الصوتية في Cloudflare Pages

أضف في **Settings → Variables and secrets** للبيئة Production:

| المتغير | الحالة | القيمة |
|---|---|---|
| `BAREEQ_TTS_PROVIDER` | مطلوب لهذا الإصدار | `gemini` — نوعه Text |
| `GEMINI_API_KEY` | مطلوب لأول توليد أو عند تغير مقال | مفتاح Google AI Studio — نوعه Secret |
| `GEMINI_TTS_MIN_INTERVAL_MS` | اختياري | `6500` لتقليل اصطدام الطبقة المجانية بحد الطلبات |
| `OPENAI_API_KEY` | غير مطلوب | لا تغيّر خطة OpenAI ولا تضف مفتاحه لهذا الإصدار |
| `AZURE_SPEECH_KEY` | غير مطلوب | احتفظ به فقط إذا أردت مسار Azure القديم |

لا تضع قيمة `GEMINI_API_KEY` في ملف داخل المستودع أو في المحادثة. يستخدمه سكربت البناء على الخادم فقط، ولا يصل إلى HTML أو JavaScript أو متصفح الزائر. إذا غاب المفتاح في أول نشر يفشل النشر الجديد بأمان وتبقى النسخة الحية السابقة فعالة.

## الرفع الصحيح — استبدال نظيف

1. فك ضغط الحزمة في مجلد مستقل.
2. افتح جذر مستودع GitHub الحالي واحتفظ بمجلد `.git` الخاص به.
3. لهذا الإصلاح الصغير، انسخ **محتويات** حزمة V4.17.2 فوق جذر المستودع الحالي ووافق على الاستبدال؛ لا تحذف ملفات المشروع أو `.git`.
4. في GitHub Desktop راجع الملفات المعدلة، خصوصًا CSS وشيفرة الصوت وملفات مراجعة النطق، قبل تنفيذ Commit.
5. تحقق من متغيرات Cloudflare، ثم استخدم Summary وDescription في `docs/دليل-النشر-والرجوع-v4.17.2.md` واختر **Commit to main** و**Push origin**.
6. انتظر حالة **Success** في Cloudflare Pages.
7. افتح النطاق الرسمي والرئيسية والمقالات ومقالًا كاملًا في نافذة خاصة وعلى هاتف.

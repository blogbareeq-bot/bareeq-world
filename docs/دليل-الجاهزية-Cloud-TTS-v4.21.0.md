# دليل الجاهزية قبل تفعيل Google Cloud TTS — بريق V4.21.0

## الحالة التي يسلّمها هذا الإصدار

- المشروع المستهدف يبقى `bareeq-tts`؛ لا حاجة إلى مشروع جديد ولا إلى Cloud Run ولا إلى إعادة بناء الموقع على Vertex.
- المسار الإنتاجي المجهّز هو **Cloud Text-to-Speech** بالنموذج العام المستقر `gemini-2.5-flash-tts`، والصوت `Sadaltager`، واللغة العربية `ar-EG`، وخرج MP3 مباشر.
- المقالان اللذان يملكان Sadaltager متوافقًا يبقيان من Production Cache دون إعادة توليد:
  - `ai-agents-future-now`
  - `ai-as-coworker-future-of-human-work`
- قائمة التوليد المستهدفة بعد التفعيل هي **11 مقالًا** فقط.
- الوضع الافتراضي آمن: `BAREEQ_CLOUD_TTS_ACTIVATE=0`. في هذا الوضع ينفّذ البناء سياسة V4.20 الحالية ولا يرسل أي طلب Cloud TTS.
- اختبارات الحزمة محلية/وهمية فقط؛ لم تُستخدم فوترة، ولم تُرسل استدعاءات مدفوعة، ولم يُفعّل أي حساب.

## الخطوة الحالية قبل التفعيل

لا تعِد تقديم نموذج فتح الحساب لدى CNTXT. بما أن مهلة الرد المذكورة مضت، افتح طلب **Support / متابعة onboarding** لدى CNTXT واطلب ربط Cloud Billing Account السعودي بالمشروع الحالي `bareeq-tts`، مع إرفاق رقم الطلب الأول وتاريخه.

**لا تفعّل** `BAREEQ_CLOUD_TTS_ACTIVATE=1` قبل اكتمال جميع البنود التالية.

## بوابة التفعيل بعد وصول رد CNTXT

1. اربط Billing Account السعودي بالمشروع `bareeq-tts` وتحقق من ظهور Billing: active.
2. فعّل **Cloud Text-to-Speech API** على المشروع نفسه.
3. امنح هوية البناء إذن `aiplatform.endpoints.predict` عبر الدور `roles/aiplatform.user`، وتأكد من وجود إذن `serviceusage.services.use`.
4. أنشئ Service Account مخصصًا للبناء بأقل صلاحيات لازمة، ولا تضع المفتاح في المستودع.
5. أضف في Cloudflare Pages:
   - Variable: `GOOGLE_CLOUD_PROJECT=bareeq-tts`
   - Variable: `GOOGLE_CLOUD_TTS_REGION=global`
   - Secret مشفّر: `GOOGLE_SERVICE_ACCOUNT_JSON` ويحتوي ملف حساب الخدمة كاملًا.
   - اترك `BAREEQ_CLOUD_TTS_ACTIVATE=0` حتى نجاح العينة الصوتية ومراجعتها يدويًا.
6. شغّل التخطيط الآمن محليًا: `npm run plan:audio:cloud:pending`. هذه الخطوة لا تحتاج مفتاحًا ولا ترسل طلبات.
7. نفّذ عينة مدفوعة واحدة فقط بعد الموافقة الصريحة:
   - اضبط مؤقتًا `BAREEQ_CLOUD_TTS_ACTIVATE=1` في جلسة محلية آمنة.
   - شغّل `npm run smoke:audio:cloud:live`.
   - استمع إلى `cloud-tts-smoke.mp3` وتحقق من النطق، والسرعة، وغياب الهمس أو الإضافة إلى النص.
   - أعد المتغير إلى `0` فور انتهاء العينة.
8. بعد قبول العينة، اضبط `BAREEQ_CLOUD_TTS_ACTIVATE=1` في Cloudflare ثم نفّذ Push واحدًا. سيحتفظ البناء بالمقالين المكتملين ويولّد/يستعيد 11 مقالًا، مع فشل مغلق إذا نقص أي ملف أو manifest.
9. بعد نجاح النشر، افحص ثلاثة مقالات على الأقل من البداية والمنتصف والنهاية، ثم نفّذ Redeploy واحدًا للتحقق أن Production Cache يخفض الطلبات الجديدة إلى صفر.

## حواجز التكلفة والسلامة

- أقصى نص افتراضي في الطلب: 3200 بايت UTF-8، تحت حد Google البالغ 4000 بايت للحقل.
- أقصى عدد افتراضي: 100 طلب في البناء.
- أقصى أحرف افتراضي: 120,000 حرف في البناء.
- التوليد متسلسل بفاصل 500ms على الأقل، والملفات تُنشأ داخل مجلد مؤقت ثم تُنقل ذريًا بعد اكتمال المقال.
- أي غياب للفوترة، أو IAM، أو بيانات الاعتماد، أو علم التفعيل يؤدي إلى توقف آمن قبل النشر.
- لا تُخزَّن بيانات اعتماد أو رموز وصول في HTML أو manifest أو تقارير البناء.

## تنبيه استهلاك Azure الاحتياطي

قبل أي تشغيل Azure مقصود، انسخ استهلاك الشهر الحالي من Azure Portal إلى `AZURE_SPEECH_MONTHLY_USED_CHARS`. سيحسب البناء الاستهلاك المتوقع بعد التشغيل، ويحذر عند 400,000 حرف، ويتوقف قبل تجاوز السقف الشهري المضبوط. إذا تُرك المتغير فارغًا يظهر تحذير صريح بأن المراقبة التراكمية غير متاحة.

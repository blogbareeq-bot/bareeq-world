# دليل المرحلة الثانية لنظام بريق الصوتي — V4.14.0

## النتيجة

تضيف هذه المرحلة مسارًا آمنًا وقابلًا للتكرار لتوليد المرشحين الحقيقيين لمختبر بريق، من دون تغيير الصوت المنشور أو إدخال مفاتيح الخدمات في الموقع أو Git.

التشكيلة المستهدفة في جلسة المقارنة:

| المرشح | النموذج/الصوت | الغرض |
|---|---|---|
| Azure الحالي | `ar-SA-HamedNeural` | خط أساس الإنتاج الحالي |
| OpenAI | `gpt-4o-mini-tts-2025-12-15` / `cedar` | تحكم بالنبرة عبر تعليمات طبيعية |
| ElevenLabs | `eleven_multilingual_v2` | الثبات في السرد الطويل |
| ElevenLabs | `eleven_v3` | التعبير على الصوت نفسه للمقارنة العادلة |
| Google | `gemini-2.5-flash-tts` / `Charon` / `ar-001` | سرد توليدي قابل للتحكم |
| Munsit | `faseeh-v1-preview` / صوت يحدده الحساب | مرشح عربي أولًا |

وجود النموذج في التشكيلة لا يعني اعتماده للإنتاج؛ القرار النهائي ينتج من التقييم الأعمى فقط.

## حدود المرحلة

- لا يُعاد توليد المقالات الأحد عشر.
- لا يتغير مشغل الموقع أو Azure الحالي.
- لا تتصل صفحة المختبر بالمزودين؛ التوليد يتم مسبقًا من جهاز موثوق.
- لا يُنشر `.voice-lab/` ولا ملفات النتائج أو مفتاح الكشف.
- لا توجد تكلفة بمجرد رفع V4.14.0 أو تشغيل `npm run build`.
- التوليد المدفوع لا يحدث إلا بأمر `voice:lab:generate` واختيار صريح للمرشحين.

## إعداد الأسرار

انسخ ملف المثال محليًا:

```text
.env.voice-lab.example → .env.voice-lab
```

ثم ضع القيم في النسخة المحلية فقط. الملف الحقيقي مستبعد من Git، بينما ملف المثال لا يحتوي أسرارًا.

المتغيرات:

| المزود | المطلوب |
|---|---|
| OpenAI | `OPENAI_API_KEY` |
| ElevenLabs | `ELEVENLABS_API_KEY` و`ELEVENLABS_VOICE_ID` |
| Google | `GOOGLE_CLOUD_PROJECT` مع `GOOGLE_CLOUD_ACCESS_TOKEN`، أو `GOOGLE_APPLICATION_CREDENTIALS` لملف service account |
| Munsit | `MUNSIT_API_KEY` و`MUNSIT_VOICE_ID` وسعر الحساب في `MUNSIT_COST_PER_1000_CHARS_USD` |

لا ترسل المفتاح في محادثة، ولا تضعه في `candidates.json`، ولا تضفه كمتغير عام داخل صفحات Cloudflare. المختبر محلي، لذلك لا يحتاج الزائر ولا المتصفح إلى أي مفتاح.

## اختيار صوت ElevenLabs وMunsit

بعد إضافة مفتاح المزود:

```bash
npm run voice:lab:voices -- --provider=elevenlabs
npm run voice:lab:voices -- --provider=munsit
```

اختر معرفًا واحدًا لـElevenLabs واستخدمه مع النموذجين v2 وv3. تغيير الصوت بين النموذجين يخلط أثر «النموذج» بأثر «هوية المتحدث» ويضعف عدالة المقارنة.

بالنسبة إلى Munsit، يفضّل صوت يدعم `fusha` والعربية، ثم يوضع معرفه كما أعادته الخدمة حرفيًا. لا تُنشئ المعرف بالتخمين.

## التخطيط المجاني

```bash
npm run voice:lab:plan
```

هذا الأمر:

1. يستخرج النص المنطوق المعتمد بعد تنظيف المقال وتطبيق قاموس النطق.
2. يتحقق من الحالات الست وبصماتها.
3. يحسب عدد الطلبات والحروف والتكلفة التقديرية.
4. يذكر المتغيرات الناقصة بأسمائها، من دون عرض قيمها.
5. يكتب `.voice-lab/generation-plan.json`.
6. لا يتصل بأي مزود ولا ينفق شيئًا.

في خط الأساس الحالي، يبلغ النص المنطوق 1364 حرفًا لكل مرشح، وتصبح الحروف القابلة للفوترة أعلى لـOpenAI وGoogle لأن تعليمات الأسلوب تدخل في طلبهما.

## حواجز التكلفة

الحواجز الافتراضية:

- حد إجمالي: 12,000 حرف في تشغيل واحد.
- حد تقديري: 2 دولار.
- تنبيه عند 70% ثم 85% ثم 95% من الحد.
- حظر أي مزود لا يمكن تقدير سعره.
- حظر أي مزود تنقصه بيانات المصادقة.

تسعير ElevenLabs محسوب وفق سعره المنشور لكل حرف. Google وOpenAI تقدير محافظ يعتمد على طول النص وسرعة سرد عربية مفترضة وتكلفة رموز الصوت؛ المبلغ النهائي قد يختلف. سعر Munsit يُدخل من لوحة المستخدم لأن الوثائق العامة تصف طريقة الاحتساب ولا تنشر رقمًا ثابتًا.

يمكن خفض الحد عند التنفيذ:

```bash
npm run voice:lab:generate -- --candidate=openai-cedar --max-usd=0.25
```

رفع الحد يتطلب كتابته صراحة، ولا يلغي حد الحروف.

## التوليد

لتوليد جميع المرشحين المهيئين:

```bash
npm run voice:lab:generate -- --all-enabled --max-usd=2
```

أو مرشح واحد/عدة مرشحين:

```bash
npm run voice:lab:generate -- \
  --candidate=openai-cedar \
  --candidate=google-gemini-2-5-charon \
  --max-usd=0.75
```

لا يقبل أمر التنفيذ تشغيلًا بلا `--all-enabled` أو `--candidate=ID`، لمنع نقرة أو نسخ أمر غير مقصود من إنشاء تكلفة.

## السلامة والكاش

لكل مرشح بصمة تشمل:

- المزود والنموذج والصوت.
- إعدادات السرعة والثبات والأسلوب.
- بصمات النصوص الستة.
- تعليمات النبرة لكل حالة.

عند تطابق البصمة والملفات، يستخدم الأمر الكاش ولا يرسل طلبًا. استخدم `--force` فقط عندما تريد إعادة التوليد عن قصد.

أثناء التوليد يُكتب المرشح في مجلد مؤقت، ثم:

1. تُفحص الاستجابة وأنها ليست فارغة.
2. يفحص `ffprobe` الترميز والقنوات ومعدل العينة والمدة.
3. يجب أن تقع المدة بين ثانيتين و120 ثانية.
4. لا يستبدل المرشح السابق إلا بعد اكتمال الحالات الست.
5. عند فشل أي حالة يُحذف المؤقت وتبقى النسخة السابقة سليمة.

يسجل `.voice-lab/generation-ledger.json` آخر 100 عملية: الحالة، عدد الطلبات، الحروف، البايتات والتكلفة التقديرية. لا يسجل المفاتيح.

## بناء المقارنة بعد التوليد

```bash
npm run voice:lab:build
npm run voice:lab:check
npm run voice:lab:serve
```

ثم افتح:

```text
http://127.0.0.1:4174/
```

يحوّل البناء كل المصادر إلى MP3 مجهول موحد عند `-16 LUFS`، mono 48 kHz / 96 kbps، ويبدل ترتيب المرشحين بين الحالات. لا تفتح ملف `answer-key.json` قبل تصدير التقييم.

## Nabrah

لم يُضف موصل Nabrah في هذا الإصدار لأن مواصفات طلب TTS عامة وثابتة لم تكن متاحة بما يكفي لتثبيت عقد قابل للاختبار. لا يُسمح بإنشاء endpoint أو حقول طلب بالتخمين.

عند توفر وثائق رسمية، يضاف موصل خامس وفق العقد نفسه. وحتى ذلك الوقت يمكن إدخال عيناته يدويًا فقط إذا كانت مولدة من النصوص نفسها ومرفقة ببصماتها، من دون تغيير قواعد التقييم.

## الإفصاح عند الإنتاج

إذا فاز OpenAI أو أي صوت مولّد واعتُمد لاحقًا، يجب أن توضح واجهة الموقع أن الصوت مولّد بالذكاء الاصطناعي. لا يحتاج مختبر المقارنة الأعمى إلى كشف المزود أثناء التقييم، لكن الكشف يصبح إلزاميًا عند النشر النهائي وفق سياسة المزود المعتمد.

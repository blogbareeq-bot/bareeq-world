# حزمة بريق القادمة — صوت بريق + نافذة بريق

## قرار الإصدار

الحزمة الجديدة تتكون من مسارين متوازيين لا يكتب أحدهما فوق الآخر:

1. **صوت بريق** — مسار PR #10، يعيد إصدار الصوت للمقالات ويثبت manifest وQA والنشر الذري.
2. **نافذة بريق** — هذا الفرع، يعيد تحرير كل مقال إلى قصة بصرية من 7–12 بطاقة ويثبت بصمة النص وQA التفاعلي.

لا يدمج أي مسار في `main` منفردًا. ينشأ فرع تجميع نهائي بعد نجاح المسارين، ثم يطبق عليه فحص الحزمة كاملًا قبل النشر.

## تغطية نافذة بريق

- المقالات: **15/15**.
- البطاقات: **135** (9 لكل مقال، بعد استبعاد أقسام المصادر من السرد البصري).
- المحتوى مرتبط ببصمة SHA-256 للمقال المصدر.
- لكل مقال Visual Director مختلف في المزاج واللغة البصرية مع هوية بريق الثابتة.
- لا تظهر «الخلاصة» كطريقة قراءة رابعة.
- طرق القراءة: **سطور · صدى · نافذة**.

## بوابة نافذة بريق

1. كل مقال منشور يملك قصة واحدة.
2. كل قصة بين 7 و12 بطاقة ومعرفاتها فريدة.
3. بصمة المقال لم تتغير بعد بناء القصة.
4. النص العربي ضمن حدود البطاقة ولا توجد بطاقات فارغة.
5. Deep Link، الحفظ 30 يومًا، المشاركة، RTL، Swipe، Keyboard، Focus، Escape وReduced Motion تعمل.
6. Typecheck وBuild واختبارات بريق الحالية تمر بلا تراجع.

## قاعدة السلامة

لا نشر جزئي: إذا فشل الصوت أو النافذة أو البناء أو التحقق الحي، تبقى الحزمة الحالية كما هي ولا ينشر نصف إصدار.

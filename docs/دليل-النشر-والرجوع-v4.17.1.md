# دليل نشر ورجوع Bareeq V4.17.1

## ما الذي يتغير؟

يصلح الإصدار بنية استجابة Gemini REST التي أوقفت نشر V4.17.0. يقرأ الصوت من `steps → model_output → content → audio` وفق مخطط Google الحالي ويثبت `Api-Revision: 2026-05-20`. يستمر صوت **Sadaltager** عبر `gemini-3.1-flash-tts-preview` للمقالات الأحد عشر، وتبقى ملفات MP3 الثابتة والتظليل والتقديم والرجوع والسرعات وحفظ موضع الاستماع 30 يومًا كما هي.

## قبل رفع الملفات

في Cloudflare Pages افتح:

`bareeq-world → Settings → Build → Variables and secrets`

أضف في بيئة **Production**:

| Type | Name | Value |
|---|---|---|
| Text | `BAREEQ_TTS_PROVIDER` | `gemini` |
| Secret | `GEMINI_API_KEY` | مفتاح Gemini Developer API من Google AI Studio |
| Text اختياري | `GEMINI_TTS_MIN_INTERVAL_MS` | `6500` |

لا تحذف مفاتيح Azure الآن؛ يمكن إبقاؤها للرجوع، لكنها لا تُستخدم عندما تكون قيمة المزود `gemini`. لا تغيّر خطة OpenAI ولا تضف `OPENAI_API_KEY` لهذا الإصدار.

لا تضع مفتاح Gemini في GitHub أو ملف `.env.example` أو الوصف أو المحادثة. يجب أن يبقى **Secret** مشفرًا.

## الرفع الصحيح

1. فك ضغط حزمة V4.17.1 في مجلد مستقل.
2. افتح جذر المستودع الحالي الذي يحتوي مجلد `.git`.
3. احتفظ بنسخة احتياطية من ملفات المشروع الحالية.
4. انسخ **محتويات** مجلد `bareeq-world-astro-v4.17.1-gemini-rest-hotfix` إلى جذر المستودع؛ لا تنسخ المجلد الخارجي كطبقة إضافية.
5. راجع التغييرات في GitHub Desktop.
6. نفّذ Commit ثم Push إلى `main`.

## ماذا يحدث في أول نشر؟

- يبني النظام خطة من 70 مقطعًا قصيرًا عبر 11 مقالًا وصوت واحد.
- يرسل الطلبات بتباعد افتراضي 6.5 ثانية، لذلك قد يستغرق أول توليد عدة دقائق.
- يعيد تلقائيًا أخطاء 429 و500 وانقطاعات النقل المؤقتة.
- يحوّل PCM إلى MP3 أحادي 48 kHz / 96 kbps عبر FFmpeg.
- يفحص المدة والحجم والبصمة والمزامنة وتسرب الأسرار قبل نجاح النشر.
- عند نجاح أول نشر، تستعيد البنايات اللاحقة ملفات المقالات غير المتغيرة من النطاق الحي ولا تعيد توليدها.

إذا فشل نشر جديد، تبقى آخر نسخة ناجحة على Cloudflare فعالة؛ لا تلغِها أثناء التشخيص.

## فحص ما بعد النشر

اختبر مقال «عادات ثقافية من حول العالم» كاملًا، ثم اختبر مقالًا طويلًا آخر:

1. الصوت المعروض هو `Sadaltager`.
2. مستوى الصوت طبيعي وليس هامسًا أو نَفَسيًا.
3. لا تُقرأ تعليمات الأداء أو كلمة `TRANSCRIPT`.
4. لا تُقرأ المصادر وقوائمها.
5. التشكيل الانتقائي والنطق صحيحان في البداية والمنتصف والنهاية.
6. يتغير تظليل الفقرة مع الصوت، ويعمل شريط التقديم والسرعة.
7. أوقف التشغيل وأعد فتح الصفحة للتأكد من استعادة الموضع.
8. افحص الهاتف والتابلت وسماعات الرأس، لا مكبر الحاسوب فقط.

لا تعمم الحكم من أول ثلاثين ثانية: يجب سماع مقطع من بداية المقال ووسطه ونهايته لأن النموذج تجريبي.

## الرجوع الفوري بلا توليد

الخيار الأسرع:

1. غيّر `BAREEQ_TTS_PROVIDER` في Cloudflare من `gemini` إلى `bundled`.
2. أعد نشر آخر Commit.
3. يتحقق البناء من حزمة Cedar/Hamed المقفلة ثم ينشرها بـ0 طلب توليد ومن دون مفتاح.

أو من Cloudflare Pages اختر آخر Deployment ناجح قبل V4.17.1 وأعد نشره. لا تحذف `audio-releases/` أو ملفات القفل لأنها مسار الرجوع الموثق.

## الخصوصية والتكلفة

تسعير Gemini Developer API الحالي يذكر أن إدخال وإخراج `gemini-3.1-flash-tts-preview` مجانيان في الطبقة المجانية، مع حدود استخدام قد تختلف حسب الحساب. ويذكر أيضًا أن بيانات الطبقة المجانية قد تُستخدم لتحسين منتجات Google؛ لذلك يرسل هذا المسار نصوص مقالات بريق العامة فقط، وليس مسودات خاصة أو بيانات شخصية.

## 4. سياسة الصوت في V4.21.5

التوليد الصوتي لم يعد جزءًا من Build العادي لـCloudflare.

`npm run build` يعمل في وضع **لا توليد خارجي**:

- `BAREEQ_GEMINI_FREE_ROLLOUT=0`
- `BAREEQ_CLOUD_TTS_ACTIVATE=0`

وبذلك لا يستطيع 429 أو Safety Filter في مقال غير مكتمل إسقاط نشر الموقع.

توليد صوت المقال يتم فقط من GitHub Actions عبر Workflow اليدوي:

`Generate passport article audio`

الـWorkflow يستخدم:

- `GEMINI_API_KEY` من Repository Secrets.
- `gemini-3.1-flash-tts-preview`.
- `Sadaltager`.
- Checkpoint منفصل عن مجلد الإنتاج.
- إعادة استخدام الأجزاء الناجحة في التشغيل التالي.
- عدم إنشاء `manifest.json` النهائي إلا بعد اكتمال جميع الأجزاء.

## 5. الاستكمال عند 429

المقال مخطط إلى:

- **11 جزءًا صوتيًا**.
- **81 كتلة تزامن**.

عند توقف Gemini بسبب 429 أو انتهاء ميزانية زمن التشغيل:

1. تبقى ملفات MP3 الناجحة في `.bareeq-audio-checkpoints` داخل GitHub Actions Cache.
2. لا يظهر صوت ناقص للمستخدم.
3. لا يُنشأ Manifest إنتاجي ناقص.
4. التشغيل التالي يستعيد أحدث Checkpoint ويبدأ من الأجزاء غير المكتملة فقط.
5. Cache key يتغير في كل Run، مع `restore-keys` لاستعادة أحدث نسخة متوافقة؛ لذلك لا تضيع الأجزاء الجديدة بسبب عدم قابلية GitHub Cache للاستبدال.

إذا ظهر خطأ قاتل غير 429، يوقف الـWorkflow المهمة ويحتفظ بالأجزاء السابقة الصالحة للتشخيص/الاستكمال، ولا يلتزم صوتًا نهائيًا.

## 7. حالة المقال قبل اكتمال الصوت

يجب أن يبقى في GitHub:

`draft: true`

ولا يُغيّر `publishedAt` أثناء مرحلة RC.

لا يُسمح بتحويل المقال إلى Live لمجرد أن بعض الأجزاء الصوتية اكتملت.

## 8. الانتقال من 13 إلى 14 مقالًا

`scripts/cloud-tts-rollout.mjs` في V4.21.5 أصبح Draft-aware:

- أثناء RC: `11 pending + 2 retained = 13` مقالًا منشورًا.
- بعد تحويل مقال الجوازات إلى Live: `12 pending + 2 retained = 14` تلقائيًا.

لا يوجد Publish Patch يدوي ولا بحث/استبدال للعدادات يوم النشر.

بوابات التوافق تقبل حالتي 13 و14 وتتحقق من الاتساق الفعلي.

## 9. يوم النشر — بعد AUDIO READY فقط

بعد اكتمال الصوت وفحصه يدويًا:

1. تحقق مرة أخيرة من بيانات Henley الحية.
2. حدّث `publishedAt` إلى وقت النشر الحقيقي.
3. حوّل `draft: true` إلى `draft: false`.
4. لا تغيّر جسم المقال بعد الصوت إلا إذا أعدت التوليد والبصمة.
5. شغّل `npm run build` كاملًا في V4.21.5.
6. يجب أن تنجح بوابات V4.20/V4.21.0/V4.21.1/V4.21.2/V4.21.3/V4.21.4/V4.21.5.
7. افحص `check-audio-dist`, `check-dist`, responsive, contrast, interactions وmobile ticker.
8. افحص الصفحة على الجوال والتابلت وسطح المكتب.
9. تحقق من sitemap وcanonical وSchema وSocial Card.
10. تحقق من تشغيل الصوت والSeek-to-text وحفظ موضع الاستماع.

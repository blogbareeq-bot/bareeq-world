# Bareeq Arabic Quality Gate v1

هذه البوابة هي طبقة ضمان الجودة التحريرية العربية في «بريق». هدفها منع الأخطاء القطعية قبل البناء والنشر، وإظهار الملاحظات اللغوية والأسلوبية من دون إعادة كتابة المقال تلقائيًا أو تغيير صوته التحريري.

## المبدأ

البوابة تفصل بين ثلاثة أنواع من النتائج:

1. **Blocking / Error** — يمنع البناء والنشر: بنية مقال مكسورة، frontmatter إلزامي مفقود، بقايا تعارض Git، TODO/FIXME/TBD، محارف اتجاه خفية خطرة، كتلة Markdown غير مغلقة، أو خطأ إملائي موجود في قائمة الأخطاء عالية الثقة.
2. **Warning** — لا يمنع النشر: الترقيم والمسافات، طول الجملة/الفقرة، تكرار الكلمات، قفزات العناوين، تغيّر الأرقام والروابط عند المقارنة، وملاحظات LanguageTool/CAMeL Tools.
3. **Report-only** — أسلوب وهوية: مؤشرات الصياغة النمطية أو أي مزود أسلوبي مثل Arab-Writer. هذه الطبقة لا يجوز أن تغيّر المقال تلقائيًا ولا أن تعتبر «بصمة AI» دليلًا على مصدر النص.

## الملفات

- `config/bareeq-arabic-qa.json` — السياسة والحدود والقاموس عالي الثقة.
- `scripts/bareeq-arabic-qa-core.mjs` — المحرك الحتمي، التحليل، Semantic Guard، وموصل LanguageTool.
- `scripts/bareeq-arabic-qa.mjs` — واجهة CLI والتقارير.
- `scripts/test-bareeq-arabic-qa.mjs` — اختبارات عدم الانحدار.
- `scripts/bareeq-camel-qa.py` — طبقة CAMeL Tools الاختيارية العميقة.
- `.github/workflows/arabic-quality-gate.yml` — التنفيذ في GitHub Actions.

## التشغيل

فحص كل المقالات:

```bash
node scripts/bareeq-arabic-qa.mjs --all
```

فحص المقالات المتغيرة مع مقارنة آمنة بالأصل:

```bash
node scripts/bareeq-arabic-qa.mjs --changed --base-ref origin/main
```

وضع صارم لحماية الأرقام والروابط والمختصرات أثناء إعادة الصياغة الآلية:

```bash
node scripts/bareeq-arabic-qa.mjs --changed --base-ref origin/main --strict-protected
```

تشغيل LanguageTool كطبقة استشارية:

```bash
BAREEQ_LT_URL=https://api.languagetool.org/v2/check \
node scripts/bareeq-arabic-qa.mjs --changed --base-ref origin/main --language-tool
```

تشغيل CAMeL Tools يدويًا بعد تثبيت الإصدار المثبت في سير العمل:

```bash
python -m pip install 'camel-tools==1.6.0'
python scripts/bareeq-camel-qa.py --require
```

## Semantic Guard

عند تمرير `--base-ref` تستخرج البوابة من النسخة الأساسية والنسخة المعدلة العناصر التالية:

- الروابط URL.
- عناوين البريد.
- الأرقام والنسب والتواريخ الرقمية.
- المختصرات اللاتينية الكبيرة مثل OLED وLCD وASR.

أي اختلاف يظهر كتحذير `BQA-SEM-001`. عند `--strict-protected` يتحول إلى خطأ مانع. الوضع الصارم مخصص خصوصًا لعمليات إعادة الصياغة أو التحسين الآلية؛ أما التعديل التحريري المقصود فيمكن مراجعته يدويًا قبل الاعتماد.

## LanguageTool

LanguageTool لا يملك صلاحية تعديل النص. البوابة ترسل نسخة نصية منزوعة Markdown إلى endpoint المحدد في `BAREEQ_LT_URL` وتحوّل النتائج إلى تحذيرات. تعطل الخدمة الخارجية لا يضعف البوابة الحتمية؛ لذلك تبقى طبقة LanguageTool استشارية افتراضيًا. يمكن جعل أخطاء الإملاء التي يرصدها مانعة فقط عبر `BAREEQ_LT_STRICT=1` في بيئة موثوقة ومستقرة.

## CAMeL Tools

طبقة CAMeL تستخدم tokenizer وأدوات Unicode والتشكيل العربية للتحقق من:

- الرموز التي تمزج العربية واللاتينية في token واحد.
- محارف عربية غير طبيعية بعد Unicode normalization.
- الحركات اليتيمة أو المكررة.
- سلامة المرور على التوكنات العربية عبر dediacritizer.

هي طبقة عميقة استشارية لأنها أثقل من الفحص الحتمي، وتعمل من `workflow_dispatch` عند الحاجة.

## Arab-Writer والمراجعة الأسلوبية

لا تعتمد البوابة على Arab-Writer كحارس نشر؛ لأن قواعد كشف «بصمات AI» قد تصطدم بأسلوب بريق المقصود: الخلاصات، الأسئلة الانتقالية، والعناوين المنظمة. لذلك تنفذ البوابة قواعد أسلوبية داخلية تحت المزود `bareeq-style` وتتعامل مع أي تكامل خارجي مستقبلي مع Arab-Writer بوضع **report-only** فقط.

لا يجوز لأي مزود أسلوبي:

- تعديل ملف المقال تلقائيًا.
- تغيير رقم أو نسبة أو تاريخ أو رابط أو مرجع أو مختصر تقني.
- منع النشر لمجرد وجود نمط لغوي يشتبه بأنه «مولد آليًا».

## الاستثناءات

إذا كان هناك سبب تحريري حقيقي لتجاوز قاعدة محددة، يمكن وضع تعليق واضح داخل الملف:

```html
<!-- bareeq-qa-disable BQA-LEX-001 -->
```

أو مجموعة قواعد مفصولة بفواصل. يجب أن يكون الاستثناء محدودًا ومبررًا في مراجعة PR. استخدام `*` يعطل كل قواعد البوابة داخل الملف ولذلك لا ينبغي استخدامه في المحتوى المنشور إلا لحالة استثنائية موثقة.

## تقارير CI

كل تشغيل يكتب:

- `bareeq-arabic-qa.json` — بيانات قابلة للمعالجة آليًا.
- `bareeq-arabic-qa.md` — تقرير قابل للقراءة.

ويرفع GitHub Actions هذه التقارير كـ artifacts لمدة 14 يومًا، ويضيف ملخص البوابة إلى GitHub Step Summary.

## قاعدة النشر

الطبقة الحتمية يجب أن تبقى **0 Errors / 0 Fatal**. التحذيرات لا تمنع النشر، لكنها تظهر للمراجع حتى لا تتحول البوابة إلى أداة تعيد كتابة صوت بريق أو تنتج إنذارات كاذبة كثيرة.

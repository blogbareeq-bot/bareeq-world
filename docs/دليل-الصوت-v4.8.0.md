# دليل القراءة الصوتية — بريق V4.8.0

## ما الجديد؟

أصبح نظام القراءة الصوتية يتكوّن من أربع طبقات مترابطة:

1. **نسخة صوتية مستقلة** من المقال تنظف الروابط والمراجع والجداول غير المناسبة للقراءة.
2. **تصحيح نطق انتقائي** في `scripts/speech-overrides.json` يضيف تشكيلًا أو كتابة صوتية بديلة للأسماء والمصطلحات من دون لمس النص المرئي.
3. **SSML على مستوى الفقرات** لتحسين الوقفات والبنية الصوتية قبل إرسال النص إلى Azure AI Speech.
4. **بيانات مزامنة** داخل `manifest.json` تربط أجزاء الصوت بكتل المقال، ثم يظلل المشغل الفقرة الحالية أثناء التشغيل.

## تصحيح النطق

لإصلاح كلمة أو اسم يُنطق بطريقة غير مناسبة، عدّل:

`scripts/speech-overrides.json`

يمكن إضافة تصحيح عام أو خاص بمقال واحد. مثال:

```json
{ "from": "جوزيف ناي", "to": "جُوزِف نَاي" }
```

النص البديل يستخدم في الصوت فقط ولا يظهر داخل المقال المنشور.

## تتبع الفقرة

المولد يحفظ لكل جزء MP3 قائمة كتل نصية مع نطاق نسبي داخل زمن الجزء. عند التشغيل يستخدم المتصفح `currentTime / duration` لتحديد الكتلة الحالية، ثم يضيف `is-audio-active` إلى العنصر المطابق في المقال.

التتبع مقصود على مستوى الفقرة/العنوان/عنصر القائمة، وليس على مستوى كل كلمة، حتى يبقى مريحًا في المقالات المعرفية الطويلة.

## سلوك الجوال

- التشغيل عبر HTML5 Audio وليس Web Speech API.
- التظليل يبقى عند Pause.
- زر «إيقاف» يعيد الصوت إلى البداية ويزيل التظليل.
- إذا كانت الفقرة خارج منطقة القراءة ينتقل إليها التمرير بسلاسة.
- بعد أي لمس/تمرير يدوي داخل المقال يتوقف التمرير التلقائي لمدة 8 ثوانٍ، فلا يسحب الموقع الشاشة من المستخدم.
- `prefers-reduced-motion` يحول التمرير إلى فوري ويوقف الحركات الزائدة.

## ملاحظة الدقة

V4.8.0 يستخدم مزامنة فقرة مرجحة بالزمن داخل كل MP3، وليست توقيت كلمات حرفيًا. هذا يقلل تعقيد البناء ويحافظ على مسار REST المستقر الذي نجح مع Cloudflare. إذا أصبحت مزامنة الكلمات الدقيقة مطلوبة مستقبلًا، يمكن الانتقال إلى Speech SDK وWordBoundary/Bookmark events في إصدار مستقل بعد اختبارها على بيئة النشر.

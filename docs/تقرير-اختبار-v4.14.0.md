## خلل اكتُشف وأُصلح

كشف أول اختبار متعدد المرشحين أن مسار FFmpeg القديم قد يعيد نجاح العملية ثم يترك عددًا قليلًا من ملفات الإخراج بطول صفري على Node 24. لم يظهر الخلل في اختبار المرشح الواحد في المرحلة الأولى.

عولج ذلك عبر:

1. انتظار حدث إغلاق FFmpeg صراحة بدل الاعتماد على تغليف callback عام.
2. الكتابة إلى ملف MP3 مؤقت فريد لكل عملية.
3. فحص الحد الأدنى للحجم وحساب SHA-256 قبل الاعتماد.
4. إعادة قراءة الملف بعد النقل الذري ومقارنة الحجم والبصمة.
5. فحص جميع الملفات مرة قبل نشر مجلد المختبر ومرة بعده.

بعد الإصلاح نجح بناء 36 ملفًا وفحصها مرتين متتاليتين من دون ملف صفري أو اختلاف بصمة.

## اختبار حزمة التسليم النظيفة

جُهزت حزمة المصدر من دون `node_modules/` أو `dist/` أو `.astro/` أو `.voice-lab/` أو `public/audio/` أو ملف الأسرار `.env.voice-lab`، ثم فُكت في مجلد جديد واختُبرت بوصفها مدخل التسليم نفسه:

1. سلامة ZIP والمسارات: PASS — 259 ملفًا، بلا مسارات مطلقة أو `../` أو أخطاء ضغط.
2. `npm ci`: PASS — تثبيت 250 حزمة من `package-lock.json`.
3. أُعيدت ملفات Azure الإنتاجية الثلاثون من نسخة محلية متحققة بوصفها cache fixture، من دون توليد أو اتصال مدفوع.
4. `npm run build`: PASS — 50 صفحة و30 MP3 وكل بوابات الإنتاج.
5. `voice:lab:baseline`: PASS — استخراج الحالات الست من Azure الحالي.
6. `voice:lab:build` ثم `voice:lab:check`: PASS — 6 مقاطع مجهولة، بلا تسرب هوية أو تسرب إلى الإنتاج.

استخدام cache fixture المحلي في هذه البيئة يعزل اختبار المصدر عن توفر النطاق الخارجي. عند البناء الفعلي يستطيع مولد Azure إعادة استخدام الملفات المنشورة غير المتغيرة وفق مساره الحالي.

## حدود ما أُثبت

- لم تُختبر جودة OpenAI أو ElevenLabs أو Google أو Munsit سمعيًا بعد؛ يلزم توليد حقيقي.
- لم يُعتمد فائز، ولم يتغير صوت Azure المنشور.
- لم تُعد توليد مكتبة المقالات الأحد عشر.
- Nabrah غير موصول لأن مواصفات API عامة وثابتة لم تتوفر بما يكفي لبناء عقد يمكن اختباره دون تخمين.
- الاختبار التالي المسموح: إضافة المفاتيح محليًا، مراجعة خطة التكلفة، توليد الحالات الست فقط، ثم إجراء جلسة تقييم أعمى واحدة.

# تقرير اختبار بريق V4.7.0 — Azure AI Speech

## نطاق التغيير
الانتقال من Google Chirp 3 HD إلى Microsoft Azure AI Speech مع الحفاظ على مشغل HTML5 Audio وإصلاح الجوال الموجود في V4.6.0.

## الاختبارات المنفذة قبل التسليم
- فحص صياغة JavaScript/MJS للملفات المعدلة.
- فحص Reading Modes لجميع المقالات المنشورة: 11/11.
- فحص بنية الجوال ومنع `speechSynthesis` واعتماد HTML5 Audio.
- فحص middleware والفهرسة للنطاق الرسمي والمعاينة.
- تشغيل `generate-audio.mjs --plan`: 11 مقالًا، 80,475 حرفًا منطوقًا، 17 طلب توليد فقط.
- اختبار تكاملي لمولد Azure على خادم API محاكي: اختيار `ar-SA-HamedNeural`، إرسال SSML، مفتاح الاشتراك في header، إخراج MP3 48kHz/192kbps، وإنشاء 11 manifest و17 MP3.
- اختبار مسار 429: أعاد المحاولة ثم أكمل توليد المقال بنجاح.
- فحص ناتج صوتي تجريبي عبر `check-audio-dist.mjs`: 17/17 أجزاء موجودة وبالمزود/اللغة/الصيغة الصحيحة.
- فحص عدم تضمين قيمة المفتاح السري أو اسمه في ناتج الإنتاج الصوتي.
- فحص أن عدد الطلبات (17) أقل من حد F0 البالغ 20 عملية في 60 ثانية، مع وجود منظم 3200ms بين عمليات التوليد في الإنتاج.
- التأكد من أن ملفات MP3 التجريبية المستخدمة للاختبار لم تدخل في حزمة التسليم؛ أول نشر يولد الصوت الحقيقي باستخدام Secret في Cloudflare.

## الاختبار الذي يتم في Cloudflare فقط
الاتصال الحقيقي بمورد Azure الخاص بمالك الموقع لا يمكن اختباره خارج Cloudflare لأن `AZURE_SPEECH_KEY` لا يُسلّم ولا يُكشف. لذلك يعتبر أول Build في Cloudflare اختبار التكامل الحي النهائي مع Azure. بوابة البناء ستفشل تلقائيًا إذا رفض Azure المفتاح/المنطقة/الصوت أو لم يُنتج MP3 كاملًا.

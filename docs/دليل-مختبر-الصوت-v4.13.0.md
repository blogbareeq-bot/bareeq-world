# دليل Bareeq Voice Lab — الإصدار 4.13.0

## الغرض

مختبر بريق الصوتي أداة محلية لمقارنة محركات وأصوات متعددة على النصوص نفسها من دون عرض اسم الشركة أو النموذج أو الصوت أثناء التقييم. لا يحل المختبر محل نظام القراءة المنشور، ولا يغيّر Azure الحالي، ولا يدخل في صفحات الإنتاج.

الهدف من المرحلة الأولى هو تثبيت **طريقة عادلة وقابلة للتكرار للاختيار** قبل دفع تكلفة توليد مكتبة المقالات كاملة.

## لماذا هو محلي وليس «صفحة سرية» في الموقع؟

الرابط المخفي في موقع ثابت ليس حماية حقيقية؛ يمكن اكتشافه من ملفات البناء أو السجلات. لذلك يوجد المختبر داخل `.voice-lab/site/` فقط، ويخدمه خادم مربوط بعنوان الجهاز المحلي `127.0.0.1`.

- لا يُضاف إلى `dist/`.
- لا يدخل خريطة الموقع أو RSS.
- لا يظهر لمحركات البحث.
- لا يرسل التقييمات إلى خادم.
- ملف كشف الهوية `.voice-lab/answer-key.json` يقع خارج مجلد العرض.
- المجلد `.voice-lab/` مستبعد من Git حتى لا تُرفع العينات أو النتائج أو مفتاح الكشف بالخطأ.

## حالات الاختبار الست

| الحالة | ما تختبره |
|---|---|
| السرد الأدبي الدافئ | التنغيم والدفء والوقفات في جمل أدبية طويلة |
| المصطلحات التقنية | الانتقال بين العربية والإنجليزية من دون كسر الإيقاع |
| الأرقام والاقتصاد | قراءة الأعداد والنسب والعملات بوضوح |
| الكلمات العربية الملتبسة | أثر التشكيل الانتقائي في أفعال وصيغ مخاطبة حساسة |
| السرد العلمي الوثائقي | الوضوح والحضور في نص علمي وصفي |
| الأسماء والثقافات | الدول والمنظمات والسنوات داخل سرد معرفي |

مدة العينات الحالية بين نحو 19 و27 ثانية؛ أي قرابة دقيقتين و24 ثانية لكل صوت عبر الحالات الست.

## معايير التقييم

كل صوت يحصل على درجة من 1 إلى 5 في:

1. طبيعية الصوت.
2. سلامة النطق.
3. الإيقاع والوقفات.
4. التعبير الملائم للنص.
5. راحة الاستماع إلى مقال كامل.

يوجد أيضًا اختيار «أفضل صوت» لكل حالة وحقل ملاحظات لتسجيل الكلمات الخاطئة أو الوقفات الغريبة أو المبالغة التعبيرية.

## ضمان عدالة المقارنة

- النص المنطوق المعتمد يُسحب من مسار بريق نفسه بعد تنظيف Markdown وتطبيق قاموس النطق.
- لكل نص بصمة SHA-256، ويرفض البناء مرشحًا لا يطابق البصمة أو النص المعتمد.
- ترتيب الأصوات يتغير مستقلًا داخل كل حالة، فلا يصبح «الصوت أ» مزودًا ثابتًا في جميع الحالات.
- أسماء الملفات المعروضة مجهولة ولا تحتوي اسم المزود أو الصوت.
- تزال بيانات MP3 الوصفية.
- توحّد الجهارة إلى `-16 LUFS`، والذروة إلى `-1.5 dBTP`، والصيغة إلى mono 48 kHz / 96 kbps.
- مفتاح الكشف منفصل عن ملفات العرض.

التوحيد يجعل المقارنة أكثر إنصافًا، لكنه لا يخفي فروق الضغط الأصلية بالكامل؛ لذلك ينبغي أن تولّد خدمات المرحلة الثانية بأعلى صيغة مستقرة متاحة ثم تُطبّق عليها المعالجة الموحدة مرة واحدة.

## التشغيل

بعد تثبيت الاعتمادات:

```bash
npm ci
npm run voice:lab
npm run voice:lab:serve
```

افتح:

```text
http://127.0.0.1:4174/
```

الأمر `voice:lab` ينفذ بالتسلسل:

1. استعادة صوت Azure المنشور إن لم يكن موجودًا محليًا؛ لا يعيد توليده ما دام مطابقًا.
2. استخراج عينات خط الأساس.
3. بناء ترتيب المقارنة العمياء.
4. تشغيل فحص يمنع تسرب الهوية أو الملفات إلى الإنتاج.

يمكن تثبيت ترتيب المرشحين لإعادة الجلسة نفسها بوضع قيمة محلية في:

```text
BAREEQ_VOICE_LAB_SEED
```

اتركها فارغة للحصول على ترتيب جديد في كل بناء.

## قواعد جلسة التقييم

- استخدم السماعة والجهاز نفسيهما لجميع الأصوات.
- أجرِ الجلسة في مكان هادئ وبسرعة تشغيل 1×.
- لا تستمع إلى العينة أكثر من مرتين قبل التقييم إلا عند الاشتباه في كلمة محددة.
- لا تفتح `answer-key.json` ولا ملفات `candidate.json` قبل تصدير النتيجة.
- عند مشاركة التقييم مع شخص ثانٍ، ابنِ المختبر مرة واحدة وشاركه مجلد `site/` فقط؛ لا تشارك المجلد الأب.
- لا تعتمد الفائز العام وحده: قد يكون صوت أدبي ممتازًا لكنه ضعيف في التقنية أو الأرقام.

## تصدير النتائج وكشفها

اضغط «تصدير النتائج» من الصفحة. بعد انتهاء التقييم شغّل:

```bash
npm run voice:lab:reveal -- /المسار/إلى/bareeq-voice-lab-results-YYYY-MM-DD.json
```

ينتج الملف:

```text
.voice-lab/revealed-results.json
```

ويعرض المتوسط العام، ومتوسط كل معيار، وعدد مرات الفوز لكل مزود وصوت.

## إضافة المرشحين في المرحلة الثانية

المختبر محايد تجاه المزود. كل مرشح يوضع في:

```text
.voice-lab/input/<candidate-id>/
```

ويحتوي `candidate.json` وستة ملفات MP3. يجب أن يثبت كل ملف ارتباطه بالنص المعتمد عبر `spokenText` المطابق أو `textSha256`.

لن تُخزن مفاتيح الخدمات في هذا المجلد أو في Git. ستقرأ موصلات المرحلة الثانية المفاتيح من متغيرات البيئة المحلية فقط، وتكتب الصوت والبيانات اللازمة إلى مجلد الإدخال المستبعد.

المرشح الوحيد في المرحلة الأولى هو خط الأساس المنشور: `ar-SA-HamedNeural`. وجود مرشح واحد يثبت سلامة المختبر، لكنه **لا ينتج حكم مقارنة**. يبدأ الاختبار الحقيقي بعد إضافة ما لا يقل عن أربعة مرشحين آخرين.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run voice:lab:baseline` | استخراج عينات Azure الحالية |
| `npm run voice:lab:build` | بناء الصفحة العمياء ومفتاح الكشف |
| `npm run voice:lab:check` | فحص الصوت والهوية والعزل عن الإنتاج |
| `npm run voice:lab:serve` | تشغيل الخادم المحلي |
| `npm run voice:lab:reveal -- <results.json>` | كشف الهوية وترتيب النتائج بعد التقييم |
| `npm run voice:lab` | تنفيذ الاستعادة والاستخراج والبناء والفحص معًا |

## ما لم تنفذه المرحلة الأولى بعد

- لا توجد اتصالات بـElevenLabs أو Google أو OpenAI أو Nabrah أو Munsit.
- لا توجد مفاتيح جديدة أو تكلفة جديدة.
- لا يوجد اختيار نهائي للصوت.
- لم يُعد توليد المقالات الأحد عشر.

هذه الحدود مقصودة: أولًا نثبت المختبر وقواعد العدالة، ثم نضيف الموصلات ونولد نحو ألف حرف لكل صوت فقط، وبعد الاختيار نعيد توليد المكتبة مرة واحدة.

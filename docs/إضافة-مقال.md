# إضافة مقال إلى عالم بريق

يعتمد V4.2 على ملفين بصريين منفصلين لكل مقال حتى يبقى الغلاف كاملًا داخل صفحة المقال، وتظهر الصورة الرمزية بلا قص أو عنوان مكرر داخل البطاقات.

## 1. ملفات المقال والصور

استخدم الاسم الأساسي نفسه للملفات الثلاثة، مثل `my-new-article`:

1. المقال: `src/content/posts/my-new-article.md`
2. غلاف المقال الأصلي: `public/images/posts/my-new-article.webp`
3. مصدر الصورة الرمزية: `assets/thumbnails-source/my-new-article.webp`

مواصفات الصورة الرمزية:

- النسبة: `16:9`.
- المقاس الموصى به: `1600×900` بكسل.
- WebP بجودة جيدة، ويُفضّل ألا يتجاوز المصدر 250KB.
- بلا عنوان أو شعار أو كتابة داخل الصورة.
- اجعل العنصر المهم قريبًا من الوسط، مع مساحة تنفّس آمنة حوله.
- حافظ على ألوان بريق: الكحلي، والتركوازي، والذهبي، والكريمي.

## 2. نموذج Frontmatter

```yaml
---
title: "عنوان المقال"
description: "وصف واضح بين 70 و160 حرفًا يشرح فائدة المقال للقارئ."
publishedAt: "2026-08-08T06:40:00.000Z"
updatedAt: "2026-08-08T06:40:00.000Z"
category: "ببساطة…"
categorySlug: "simply"
seriesSlug: "technology-simply"
featured: false
draft: false
author: "فريق بريق"
tags: ["معرفة", "تبسيط"]
image: "/images/posts/my-new-article.webp"
imageAlt: "وصف موضوعي لغلاف المقال"
imageWidth: 1600
imageHeight: 900
thumbnail: "/images/thumbnails/my-new-article.webp"
thumbnailAlt: "وصف موضوعي للصورة الرمزية"
---
```

القيم المسموحة لـ`categorySlug` هي:

- `atyaf-al-aql`
- `bareeq-books`
- `window-on-world`
- `future-now`
- `simply`

القيم الاختيارية المسموحة لـ`seriesSlug` هي: `mind-and-decisions` و`technology-simply` و`windows-to-world` و`books-for-life`. لا تضف السلسلة إلا إذا كان المقال جزءًا حقيقيًا من مسار مترابط.

قواعد التحرير الآلية:

- يُحسب زمن القراءة من نص المقال؛ لا حاجة إلى إدخاله يدويًا.
- استخدم وسمين دقيقين كحد أقصى، ولا تكرر اسم القسم كوسم.
- لا تُفهرس صفحة وسم أو سلسلة مستقلة قبل أن تضم ثلاثة مقالات، تجنبًا للأرشيفات الرقيقة.
- أضف رابطًا داخليًا سياقيًا واحدًا على الأقل إلى مادة ذات صلة، وروابط مباشرة إلى المصادر الأساسية للادعاءات المهمة.

## 3. البناء والتحقق

نفّذ:

```bash
npm ci
npm run build
```

ينشئ البناء تلقائيًا:

- أربعة مقاسات للغلاف الأصلي داخل `public/images/generated/`.
- أربعة مقاسات 16:9 للصورة الرمزية داخل `public/images/thumbnails/`.
- صورة مشاركة اجتماعية 1200×630 داخل `public/images/social/`.

ويتوقف البناء إذا كان غلاف المقال بلا صورة رمزية مطابقة، أو كانت الصورة الرمزية المولدة بأبعاد خاطئة، أو وُجد رابط أو وصف أو عنوان أو خاصية وصول غير سليمة.

## 4. النشر من GitHub

بعد نجاح البناء:

1. راجع الصورة الرمزية في الرئيسية وصفحة المقالات والقائمة المنسدلة.
2. تأكد أن غلاف المقال يظهر كاملًا داخل صفحة المقال.
3. أنشئ Commit واضحًا ثم ارفع إلى `main`.
4. انتظر نجاح Cloudflare Pages وافتح المقال على الجوال وسطح المكتب.

لإخفاء المقال مؤقتًا دون حذفه استخدم:

```yaml
draft: true
```

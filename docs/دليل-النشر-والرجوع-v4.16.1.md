# دليل نشر ورجوع Bareeq V4.16.1

## القرار المعتمد

هذا هو **الخيار الأول**: تسجيل Cedar الحقيقي لمقال «عادات ثقافية من حول العالم»، مع إعادة استخدام تسجيلات Azure Hamed المنشورة والمعتمدة للمقالات العشرة الأخرى.

- لا يحتاج تغيير خطة OpenAI.
- لا يحتاج `OPENAI_API_KEY`.
- لا يحتاج `AZURE_SPEECH_KEY`.
- لا ينفذ Cloudflare أي طلب توليد صوتي مدفوع.
- يحفظ المشغّل موضع الاستماع على الجهاز والمتصفح نفسه لمدة 30 يومًا.

## إعداد Cloudflare Pages

إعدادات البناء:

| الحقل | القيمة |
|---|---|
| Production branch | `main` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | فارغ |
| Node.js | Node 22 حديث، مثل `22.16.0` |

في **Workers & Pages → bareeq-world → Settings → Variables and Secrets**:

| المتغير | الإجراء في V4.16.1 |
|---|---|
| `BAREEQ_TTS_PROVIDER` | غيّره إلى `bundled` أو احذفه؛ القيمة الافتراضية `bundled` |
| `OPENAI_API_KEY` | غير مطلوب؛ يمكن حذفه إن أُضيف لهذا النشر فقط |
| `AZURE_SPEECH_KEY` | غير مطلوب |
| `BAREEQ_AUDIO_ALLOW_PARTIAL` | يجب ألا يكون موجودًا في Production |

إذا كان `BAREEQ_TTS_PROVIDER=openai` ما زال مضبوطًا من المحاولة السابقة، **غيّره إلى `bundled` قبل إعادة النشر**؛ وإلا سيُطلب مفتاح OpenAI مجددًا لأنك تكون قد اخترت مسار الترقية المدفوعة صراحة.

## ماذا يحدث في البناء؟

1. يتحقق من جميع إصلاحات المصدر والجوال والأمان وSEO السابقة.
2. يفحص 29 ملف Azure Hamed المثبتة للمقالات العشرة: SHA-256 والحجم والمدة والصيغة.
3. يطابق 751 كتلة مزامنة Hamed مع نصوص المقالات الحالية، ويوقف البناء عند أي اختلاف.
4. يستورد Cedar Studio الحقيقي للمقال الجديد، ويفحص ملفه الكامل و21 جزء مصدر و21 علامة مزامنة.
5. يؤكد أن الخطة تحتوي 11 مقالًا و0 طلب توليد و0 حرف مدفوع.
6. يبني 50 صفحة ثم يفحص الصوت والروابط والوصول والاستجابة والتباين والتفاعلات.

لا يتصل الوضع `bundled` بـOpenAI أو Azure أو بالموقع الحي أثناء تجهيز الصوت.

1. فك ضغط حزمة V4.16.1 في مجلد مستقل.
2. افتح مجلد مستودع بريق الحالي واحتفظ بمجلد `.git` الموجود فيه.
3. خذ نسخة احتياطية من الملفات الحالية.
4. انسخ **محتويات** مجلد V4.16.1 إلى جذر المستودع، لا المجلد الخارجي نفسه.
5. اسمح باستبدال الملفات ذات الأسماء المتطابقة، ولا تنسخ `node_modules` أو `dist`.
6. افتح GitHub Desktop وراجع التغييرات، ثم استخدم:

## فحص ما بعد النشر

اختبر على الأقل:

1. مقال «عادات ثقافية من حول العالم»: الصوت Cedar، المدة 4:41، و21 موضع مزامنة.
2. مقال «لماذا لا تسقط الأقمار الصناعية من السماء؟»: الصوت حامد، يعمل عبر أربعة أجزاء من دون ظهور أرقام الأجزاء للمستخدم.
3. أوقف الصوت في المنتصف، أغلق الصفحة، ثم عد وتأكد من ظهور «متابعة الاستماع» والعودة إلى الموضع نفسه.
4. تحقق من شريط التقديم والسرعات والإيقاف وحذف الموضع عند الإكمال أو الضغط على «إيقاف».
5. تحقق من الرئيسية والمقالات والبحث و`/sitemap.xml` و`/robots.txt` ومن عدم وجود تمرير أفقي على الجوال.

## الرجوع السريع

1. افتح **Cloudflare Pages → Deployments**.
2. اختر آخر نشر ناجح قبل V4.16.1.
3. استخدم **Rollback to this deployment**.

أو أعد Commit الإصدار السابق من Git. لأن Cloudflare يبدّل النشر كاملًا، لا يرى الزائر نصف إصدار صوتي.

## الترقية الصوتية لاحقًا

مسارا OpenAI وAzure ما زالا موجودين، لكنهما لا يعملان إلا باختيار صريح:

- `BAREEQ_TTS_PROVIDER=openai`: Cedar + Marin، يحتاج مفتاحًا وقد يترتب عليه استهلاك مدفوع.
- `BAREEQ_TTS_PROVIDER=azure`: Hamed + Zariyah، يحتاج مفتاح المورد وحساب حصته.

لا تغيّر الوضع الافتراضي إلا بعد مراجعة خطة الطلبات والتكلفة.

# تقرير اختبار Bareeq v4.12.0 — Mobile Categories + Arabic Speech QA

**التاريخ:** 12 أغسطس 2026  
**النطاق:** فحص المصدر قبل التسليم؛ Cloudflare Pages يبقى اختبار الإنتاج النهائي.

## الهدف

إصلاح تراجع أخفى شريط الأقسام على الجوال، ورفع جودة القراءة الصوتية العربية بإضافة طبقة مراجعة نطق مستقلة عن النص المرئي من دون إدخال خدمة مدفوعة جديدة.

## نتيجة شريط الأقسام

- السبب المؤكد: القاعدة الأساسية `.category-mobile-link{display:none}` بقيت فعالة لأن نسخة <=900px لم تُعد `display:flex`.
- الإصلاح: إظهار الرابط صراحةً في breakpoint <=900px مع `flex-wrap` وبدون `overflow-x:auto`.
- أضيفت بوابات تمنع تكرار التراجع، وتتحقق من ظهور `.category-mobile-link` فعليًا عند 390px و768px بعد تصغير CSS في فحص الإنتاج.

## نتيجة القراءة العربية

- تمت مراجعة المقالات المنشورة الأحد عشر وربط كل مقال ببصمة SHA-256 لنصه في `scripts/speech-review.json`.
- تم التحقق من **48 تصحيحًا سياقيًا** للنطق قبل التوليد.
- المثال المكتشف أصبح في النص الصوتي فقط: `تَصَرَّفْتَ` و`عَرَفْتَ` بينما يبقى النص المرئي بلا تغيير.
- تغطي القواعد أيضًا مواضع ملتبسة مثل: `اسْتَطَعْتَ`، `كُنْتَ`، `رَتَّبْتَ`، `شَعَرْتَ`، `رَأَيْتَ`، `الْتَزَمْتَ`، `نَجَحْتَ`، `مَنَحْتَ`، `سَأَلْتَ`، إضافة إلى أوامر وصيغ مخاطبة محددة سياقيًا.
- بوابة `check-arabic-speech.mjs` تفشل إذا تغير نص مقال بعد آخر مراجعة أو إذا بقيت كلمة عالية الالتباس بلا ضبط في النص المنطوق.
- لا يتم تعديل نص المقال المرئي ولا يُستخدم تشكيل آلي شامل.

## حدود الاختبار المحلي

تعذر إكمال تثبيت npm الكامل في بيئة التسليم، لذلك لم يُنفذ Astro production build كاملًا محليًا. لم تُستخدم مفاتيح Azure داخل الحزمة، ولم يتم توليد MP3 حقيقي محليًا. عند Cloudflare سيقوم `npm run build` بتشغيل نفس البوابات أولًا ثم توليد الصوت المتغير وبناء Astro وفحوص `dist`.

## بوابة الاعتماد بعد النشر

لا يُعتمد الإصدار نهائيًا قبل:

1. نجاح Cloudflare Build كاملًا.
2. ظهور الأقسام الخمسة على هاتف 390px بلا سحب أفقي.
3. اختبار مقال «عادات ثقافية…» وسماع افتتاحيته: `هل سبق أن تَصَرَّفْتَ بعفوية، ثم عَرَفْتَ...`.
4. اختبار تشغيل/إيقاف/متابعة على جهاز لوحي فعلي.

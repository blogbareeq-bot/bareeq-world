# تقرير اختبار Bareeq v4.11.0 — Launch Readiness

## الأساس

هذه الجولة مبنية فوق v4.10.0، وتستخدم تقرير التدقيق الشامل v4 كمرجع لاختيار الإصلاحات الآمنة قبل الإطلاق. لم تُنفذ البنود التي تتطلب خدمة خارجية غير مهيأة (مثل إنشاء بريد على النطاق) أو التي قد تعيد مشكلة التابلت (إزالة manifest الصوت المضمّن) أو تتطلب إعادة توليد مكتبة الصوت كاملة (خفض bitrate).

## الإصلاحات المنفذة

1. إصلاح False Positive في `check-responsive-css.mjs` لقبول الصيغة المصغرة `flex:104px` المكافئة لـ`flex:1 1 104px`.
2. شريط الأقسام: `flex-wrap`، بلا `overflow-x:auto`، وغير لاصق حتى 900px.
3. نقل breakpoint الهامبرغر إلى ≤800px.
4. H1 الرئيسية أصبح «عالم بريق — نافذتك إلى المعرفة»، وعنوان أحدث مقال H2.
5. إبقاء وصف الهيرو بسطر واحد عند ≤420px.
6. إصلاح روابط المشاركة العربية لمنع `%25D8/%25D9`.
7. فتات المسار يعرض عنوان المقال بدل «المقال».
8. TOC يضم H2 فقط.
9. المقالات المرتبطة تتطلب سلسلة مشتركة أو وسمًا مشتركًا؛ القسم وحده لا يكفي.
10. جميع السلاسل ذات مقالين فأكثر أصبحت قابلة للفهرسة ومشمولة في sitemap، مع بقاء الوسوم على عتبة 3 مقالات.
11. إضافة SearchAction متوافق مع `/search/?q=`.
12. preload لوزن IBM Plex Sans Arabic 400.
13. PWA icons: 192×192 و512×512.
14. حذف wildcard CORS من HTML فقط عبر middleware.
15. الحفاظ على Azure/HTMLAudio/inline manifest وإصلاحات التابلت دون تغيير.
16. إضافة فحص `check-launch-readiness.mjs` إلى build gate.

## ما يحتاج اختبار Cloudflare بعد الرفع

بيئة العمل المحلية لم تستطع تنفيذ `npm ci` الكامل، لذلك يبقى `npm run build` في Cloudflare هو اختبار Astro/Vite/PostCSS/Sharp النهائي. أهم نقطة Regression يجب مراقبتها هي نجاح `check-responsive-css.mjs` بعد minification؛ تم تعديل الاختبار ليقرأ القيمة دلاليًا ويقبل `104px` و`1 1 104px`.

## قرار متعمد لم يُغيّر

- البريد يبقى `blogbareeq@gmail.com` حتى إنشاء عنوان نطاق حقيقي يعمل؛ لا نستخدم عنوانًا وهميًا في الموقع أو Schema.
- لا إزالة لـ`data-audio-manifest-inline` قبل اختبار iPad/Safari حي؛ الأولوية لاستقرار تشغيل الصوت.
- لا خفض لـ48kHz/96kbps في هذه الجولة؛ يجب اختبار عينة 24kHz/48kbps سمعيًا أولًا.
- لا تغييرات جماعية على الصور أو تواريخ المقالات أو نبرة المقالات الجديدة.

## بوابة ما بعد النشر

بعد نجاح Cloudflare:

1. افتح الرئيسية عند 320/360/390/430/768/820/900/1024/1440px.
2. تأكد أن الأقسام الخمسة تظهر بلا تمرير أفقي، وأنها غير sticky عند ≤900px.
3. افتح مقالًا بمسار عربي واختبر WhatsApp/X/Facebook؛ يجب ألا يظهر `%25D8` في رابط المشاركة.
4. تحقق من `/sitemap.xml` ووجود السلاسل الأربع.
5. اختبر الصوت على نفس الجهاز اللوحي السابق: Play → Pause → Resume → Speed → Next part → Stop.
6. تحقق من H1 الرئيسية وفهرس H2 فقط وفتات المسار.

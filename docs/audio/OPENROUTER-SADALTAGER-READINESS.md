## Pilot decision rule

For each locked sample:

`delta = current production baseline errors - OpenRouter pilot errors`

Technical pilot passes only when:

- technical QA passes for all three samples;
- no sample regresses by more than one error;
- fewer than two samples regress at all;
- total delta is positive;
- at least two samples improve.

A technical pass authorizes only a human review of the evidence. Production wiring remains a separate change.

## Account/credit gate

The repository cannot inspect or purchase OpenRouter credits directly. After this branch is merged, the push workflow performs a zero-cost API-key probe using the existing `OPENROUTER_API_KEY` secret when available.

Important: `GET /api/v1/key` validates the key and key-level `limit_remaining`, but it does **not** guarantee that the shared prepaid credit pool is sufficient. A live TTS request may still return HTTP `402` if account credits are exhausted. No automatic top-up or financial transaction is performed by this workflow.

## Decision after the key probe

- **Key missing/invalid:** stop and configure/replace `OPENROUTER_API_KEY`; no audio generation.
- **Key valid:** the isolated three-sample live pilot is technically ready.
- **Live request returns 402:** OpenRouter is credit-blocked; do not retry repeatedly. The project then moves to the next non-Google engine path.
- **Live pilot passes:** review evidence, then build a separate production integration PR that uses engine/transport-aware fingerprints and preserves all exact published audio.

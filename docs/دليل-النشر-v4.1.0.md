# دليل نشر عالم بريق V4.1.0

## قبل البدء

- استخدم **استبدالًا نظيفًا** لملفات المشروع؛ لا تنسخ V4.1 فوق ملفات إصدار قديم وتترك البقايا.
- احتفظ بمجلد `.git` الخاص بالمستودع الحالي ولا تستبدله بمجلد آخر.
- تحذير LF/CRLF في GitHub Desktop معلوماتي ولا يمنع Commit أو النشر.
- احتفظ بآخر Deployment ناجح في Cloudflare حتى تتمكن من الرجوع إليه فورًا عند الحاجة.

## الرفع عبر GitHub Desktop

1. فك ضغط `bareeq-world-v4.1.0-launch-ready.zip` في مجلد مستقل.
2. افتح **Repository > Show in Explorer** من GitHub Desktop.
3. احتفظ بمجلد `.git`، وانقل بقية ملفات المشروع القديم إلى نسخة احتياطية خارج المستودع.
4. انسخ **محتويات** مجلد `bareeq-world-astro-v4.1.0-launch-ready` إلى جذر المستودع؛ لا تنسخ المجلد كطبقة إضافية.
5. عد إلى GitHub Desktop وتأكد من ظهور ملفات محذوفة قديمة وملفات V4.1 المضافة والمعدلة.
6. اكتب في Summary: `Release Bareeq V4.1.0`.
7. اختر **Commit to main** ثم **Push origin**.

لا ترفع `node_modules/` إذا أضفته محليًا؛ ملف `.gitignore` يستبعده تلقائيًا.

## إعداد Cloudflare Pages

| الحقل | القيمة |
|---|---|
| Production branch | `main` |
| Framework preset | Astro، أو None مع الإعدادات التالية |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | فارغ |
| Node.js | `22.16.0` أو إصدار Node 22 أحدث |

وجود مجلد `functions/` مقصود؛ يستخدمه Cloudflare Pages لمنع فهرسة نطاق المعاينة فقط.

## اعتماد النشر

1. افتح **Cloudflare Dashboard > Workers & Pages > bareeq-world > Deployments**.
2. تأكد أن آخر Deployment مرتبط بالـCommit الجديد وأن حالته **Success**.
3. افتح الروابط التالية في نافذة خاصة:

```text
https://bareeq-world.pages.dev/
https://bareeqworld.com/
https://bareeqworld.com/articles/
https://bareeqworld.com/search/
https://bareeqworld.com/editorial-policy/
https://bareeqworld.com/sitemap.xml
https://bareeqworld.com/robots.txt
https://bareeqworld.com/admin/
```

المتوقع لـ`/admin/` هو 404. ويجب أن يعيد النطاق الرسمي HTTP 200؛ أي 502 يعني أن ربط النطاق أو Origin ما زال يحتاج إصلاحًا في Cloudflare ولا يُعالج من ملفات القالب.

## فحص الواجهة بعد النشر

### سطح المكتب

- العرض يستفيد من الصفحة كاملة مع هوامش آمنة، ولا يوجد تمرير أفقي.
- تظهر الأقسام الخمسة فقط في الشريط العلوي، بلا «الكل» وبلا تكرار في الوسط أو التذييل.
- افتح كل Mega Menu بالماوس والنقر، ثم جرّب Tab وArrowDown وEscape.
- يجب أن تحمل أيقونات الأقسام ألوانًا مختلفة، لا أن تظهر كلها بلون النص العام.
- صور البطاقات والقائمة المنسدلة بلا كتابة داخلية، وبنسبة 16:9 من دون قص ظاهر.

### الجوال — 390px تقريبًا

- الشعار وأزرار البحث والثيم والقائمة داخل عرض الشاشة.
- شريط الأقسام يمرر أفقيًا داخل حدوده ولا يوسّع الصفحة.
- درج القائمة كامل الارتفاع، والأقسام داخله Accordion.
- البطاقات أفقية أو رأسية بتناسب طبيعي، والصورة الرمزية كاملة.
- التذييل عمود واحد؛ لا توجد كلمات مفككة أو أعمدة متداخلة.
- «روابط مهمة» و«تواصل معنا» يفتحان ويغلقان بصورة سليمة.
- البريد الإلكتروني في سطر مقروء واتجاهه من اليسار إلى اليمين.

### صفحة المقال

- غلاف المقال الأصلي يظهر كاملًا دون تشويه.
- شريط تقدم القراءة يتحرك.
- فهرس المقال يثبت على سطح المكتب ويصبح قابلًا للطي على الأجهزة المتوسطة والصغيرة.
- روابط المشاركة ونسخ الرابط تعمل.
- لا توجد صورة أخرى تحمل `fetchpriority="high"` غير غلاف المقال.

## فحص الفهرسة والترويسات

```bash
curl -I https://bareeq-world.pages.dev/
curl -I https://bareeqworld.com/
```

- `pages.dev`: يجب أن يحتوي `X-Robots-Tag: noindex, nofollow, noarchive`.
- النطاق الرسمي: يجب ألا يحتوي ترويسة مانعة للفهرسة.
- كلاهما يجب أن يحتوي سياسات الأمان الأساسية، ومنها CSP وHSTS و`nosniff`.

بعد استقرار النطاق الرسمي، أضف `https://bareeqworld.com/sitemap.xml` إلى Google Search Console.

## فحص الأداء النهائي

شغّل Lighthouse للجوال ثلاث مرات على:

1. الرئيسية.
2. صفحة المقالات.
3. أطول مقال.

اعتمد القيمة الوسيطة، وراقب خصوصًا LCP وCLS وINP. لا تُدخل إعلانات قبل تثبيت خط أساس الأداء حتى يمكن معرفة أثرها الحقيقي.

## الرجوع الآمن

إذا ظهر خلل بعد الرفع، استخدم **Rollback to this deployment** على آخر إصدار ناجح من Cloudflare Pages. لا تحذف النشر السابق، ولا تمسح الكاش قبل التأكد أن الـDeployment الجديد نجح وأنه هو المرتبط بالنطاق الرسمي.

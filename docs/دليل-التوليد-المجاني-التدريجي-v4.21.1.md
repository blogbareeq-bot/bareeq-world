# دليل التوليد المجاني التدريجي — بريق V4.21.1

## الهدف

استكمال تسجيل المقالات الـ11 المتبقية بصوت Gemini Sadaltager باستخدام الحصة المتاحة، من دون تعطيل الموقع أو حذف أصوات حامد/سيدر الحالية عند نفاد الحصة.

هذا المسار مستقل عن Google Cloud TTS المدفوع. يبقى `BAREEQ_CLOUD_TTS_ACTIVATE=0` إلى ما بعد ربط CNTXT والموافقة على التفعيل.

## ما تفعله الحزمة تلقائيًا

في كل Build إنتاجي:

1. تستورد الأصوات البديلة المعتمدة الموجودة داخل الحزمة.
2. تستعيد مقالي Sadaltager المكتملين من Production Cache.
3. تبحث في المقالات الـ11 عن أي تسجيلات Sadaltager اكتملت في عمليات نشر سابقة وتستعيدها بلا طلبات توليد.
4. تستعيد حامد للمقالات القديمة التي لم يكتمل تحويلها بعد.
5. تتحقق من وجود صوت كامل لكل المقالات الـ13 قبل المحاولة الجديدة.
6. إذا كان `GEMINI_API_KEY` موجودًا، ترتب المقالات غير المكتملة حسب عدد الأجزاء وتختار الأقصر.
7. تحاول **مقالًا واحدًا فقط** في ذلك البناء، جزءًا بعد جزء.
8. تنشر مجلد المقال الجديد ذريًا بعد اكتمال جميع MP3 وملف `manifest.json` فقط.
9. إذا استمر 429 أو انتهت مهلة البناء، تحذف المجلد المؤقت وتبقي الصوت السابق؛ يظل النشر صالحًا.

## الإعداد المطلوب مرة واحدة

1. أنشئ أو استخدم مفتاح Gemini API صالحًا من Google AI Studio.
2. في Cloudflare Pages، افتح إعدادات المشروع ثم متغيرات وSecrets بيئة **Production**.
3. تأكد من وجود Secret باسم `GEMINI_API_KEY` وقيمة المفتاح داخله.
4. لا تضع المفتاح في `.env.example` أو GitHub أو لقطة شاشة أو رسالة.
5. أبقِ `BAREEQ_CLOUD_TTS_ACTIVATE=0`.
6. لا يلزم إنشاء `BAREEQ_GEMINI_FREE_ROLLOUT`؛ قيمته الافتراضية `1`. لإيقاف المحاولات مؤقتًا فقط، أضفه بقيمة `0`.
7. إن أضفت `BAREEQ_GEMINI_FREE_ARTICLES_PER_BUILD` فتبقى قيمته `1`؛ يرفض البناء أي قيمة أخرى.

ملاحظة: شاشة Google AI Studio التي تقول **Link an API key** تخص ربط المفتاح بتلك الواجهة، ولا تؤكد أن Cloudflare يملك Secret الإنتاج. المرجع الفعلي للنشر هو إعداد `GEMINI_API_KEY` في Cloudflare.

## تطبيق الحزمة

1. فك الضغط وافتح `bareeq-world-main`.
2. انسخ جميع محتويات المجلد إلى مجلد المستودع الحالي واختر Replace للملفات المتطابقة.
3. لا تحذف مجلد `.git` ولا تستبدل مجلد المستودع نفسه.
4. في GitHub Desktop استخدم:
   - Summary: `feat: release V4.21.1 progressive Gemini audio and design-one header`
   - Description: `Release Bareeq V4.21.1 with the approved design-one header, a shortest-first one-article Gemini free-tier rollout, atomic 429-safe fallback preservation, protected Cloudflare email links, and updated local-storage privacy disclosure. Paid Cloud TTS remains locked pending CNTXT.`
5. نفّذ Commit ثم Push مرة واحدة.
6. لا تشغّل Deployments متزامنة.

## قراءة نتيجة Cloudflare

### عند نجاح مقال جديد

تظهر رسائل شبيهة بالآتي:

```text
Progressive article priority: shortest unresolved transcript first (...)
Progressive article cap: selected 1 of ... unresolved article(s)
Gemini free-tier step complete: 1 Sadaltager article(s) completed atomically
V4.21.1 free-tier deployment ready: 3/13 article(s) currently use Gemini Sadaltager
```

العدد `3/13` مثال لأول نجاح؛ يزيد تلقائيًا مع كل مقال مكتمل.

### عند نفاد الحصة 429

تظهر رسائل `Gemini progressive rollout paused` و`Safe progressive fallback`. هذه ليست خسارة للملفات: يكتمل النشر بالأصوات السابقة، ويمكن إعادة المحاولة في يوم لاحق.

### عند غياب المفتاح

تظهر رسالة أن `GEMINI_API_KEY is absent` وأن عدد طلبات التوليد صفر. الموقع يظل قابلًا للنشر، لكن لن يتقدم التحويل.

## وتيرة الاستكمال

- بعد كل نجاح، لا حاجة إلى تعديل أي قائمة يدويًا؛ النشر التالي يقرأ الموقع الحي ويكتشف التسجيل المكتمل.
- الحد الأقصى مقال واحد في كل Deployment، لذلك يحتاج إكمال 11 مقالًا إلى 11 عملية نشر ناجحة على الأقل.
- لا تكرر Redeploy في اليوم نفسه إن كانت النتيجة 429؛ انتظر تجدد الحصة ثم نفّذ Redeploy واحدًا.
- المقالات تختلف في الطول؛ الخطة الكاملة الحالية هي 81 جزءًا و95,441 حرفًا. يبدأ النظام بأقصر مقال غير مكتمل، وعدد أجزائه أربعة في حالة البداية الحالية.

## التحقق المحلي

```bash
npm ci --ignore-scripts
npm run plan:audio:gemini:pending
npm run test:audio:gemini:free
npm run audit:v4211
```

الأمر `test:audio:gemini:free` يستخدم خادمًا وهميًا محليًا ويحاكي النجاح و429؛ لا يرسل طلبًا حقيقيًا ولا يستهلك الحصة.

## الإيقاف والرجوع

- إيقاف المحاولات مع إبقاء الإصدار: اضبط `BAREEQ_GEMINI_FREE_ROLLOUT=0` ثم أعد النشر.
- لا تضبط `BAREEQ_CLOUD_TTS_ACTIVATE=1` كبديل؛ هذا مسار مدفوع مختلف.
- للرجوع الكامل، أعد نشر V4.21.0 السابق من Cloudflare أو GitHub.

# قرار وتنفيذ صوت فهد — V4.22.0

التاريخ: 25 أغسطس 2026
النطاق: جميع مقالات بريق المنشورة (15 مقالًا)

## القرار

المسار الإنتاجي الفوري هو **Microsoft Azure AI Speech بصوت `ar-KW-FahedNeural`**، بصوت واحد فقط يحمل المعرّف الداخلي `fahed`. هذا هو الصوت الذي اجتاز الاختبار السمعي الأولي لدى مالك الموقع، وهو متاح رسميًا بلهجة الكويت. يبقى Gemini 3.1 Flash TTS مسار ترقية لاحقًا عندما تستقر الحصة؛ ولا يوقف نشر صوت فهد.

لا يُستخدم التشكيل الآلي الشامل. النص المنطوق يمر بمراجعة سياقية انتقائية: تُشكّل الكلمات الملتبسة فقط، وتُحوّل الأسماء الأجنبية والاختصارات إلى نطق عربي معلن، وتُستبعد قائمة المصادر من الصوت.

## المقارنة

| الخيار | العربية/الطول | النتيجة العملية | القرار |
|---|---|---|---|
| Azure Fahed | صوت رسمي `ar-KW`، SSML، MP3 مباشر | الصوت مختبر مسبقًا، 0.5 مليون حرف شهريًا في F0، وتكامل موجود بالمشروع | الإنتاج الآن |
| Gemini 3.1 Flash TTS | `ar-EG`، توجيه أداء، مناسب للمحتوى الطويل | أداء واعد لكن المسار السابق اصطدم بالحصة/429 | ترقية لاحقة تدريجية |
| ElevenLabs v3 / Multilingual v2 | العربية مدعومة وأداء تعبيري | يحتاج اختيار صوت جديد واختبارًا وتكلفة لكل حرف | مختبر اختياري، ليس حاجزًا |
| OpenAI `gpt-4o-mini-tts` | العربية مدعومة | الوثائق تنبّه إلى أن الأصوات محسّنة للإنجليزية | ليس الاختيار العربي الأول |

## اختبار التشكيل

- فشل Mishkal في العنوان التجريبي؛ غيّر علاقات الإعراب والسياق، لذلك رُفض للتطبيق الآلي.
- أعطى CATT-ED العنوان المرجعي كاملًا بصورة صحيحة، لكنه أخطأ في عينة سياقية أوسع في المبني للمعلوم/المجهول وبعض الأفعال المتعدية، لذلك استُخدم **رأيًا ثانيًا فقط** لا محررًا تلقائيًا.
- النتيجة: مراجعة كاملة لكل مقطع مع تشكيل انتقائي للكلمات الملتبسة. لا يُقبل أي تغيير لا يمكن ربطه بتحويل معلن في ملف Speech Script.

## ما نُفّذ

- راجعت ملفات Speech Script للمقالات الخمسة عشر وربطت كل مقطع بهاش نص المصدر وبنيته.
- أصبحت نتيجة المخزون: `A=15, B=0, C=0`، دون غموض سياقي أو نص أجنبي غير محسوم في النص المنطوق.
- أُضيف المزود `azure-fahed` مستقلًا عن `azure` القديم؛ فلا تختلط ملفات فهد بحامد/زارية أو بالملفات المجمعة القديمة.
- اللغة `ar-KW`، الصوت `ar-KW-FahedNeural`، الإيقاع الافتراضي `-2%`، والصيغة `audio-48khz-96kbitrate-mono-mp3`.
- أُضيف SSML محافظ يقرأ الأرقام والنسب، ويقرأ المعرّفات الطويلة مثل ISBN رقمًا رقمًا، مع هروب XML واختبارات عقد محلية.
- قُيّدت الوجهات التي تتلقى مفتاح Azure بنطاقات Speech الرسمية تحت `microsoft.com` و`azure.com`.
- تُنتج المقالات في مجلد مؤقت، ثم تُنقل ذريًا بعد اكتمال كل الأجزاء. يسجل الـmanifest الحجم والمدة وSHA-256 لكل MP3.
- أُضيف مسار مستقل لعيّنة الاستماع، ولا يستطيع توليد المقال الكامل تجاوز البوابة من دون ملف صوت حقيقي وهاش مطابق واسم مراجع وتاريخ مراجعة.

## حجم التشغيل المحسوب

- 15 مقالًا.
- 52 طلب توليد لصوت واحد.
- 140,591 حرفًا منطوقًا تقريبًا.
- أقسام المصادر مستبعدة من القراءة.
- الخطة نفسها ترسل صفر طلبات إلى Azure.

يقع التشغيل الكامل نظريًا داخل حصة F0 البالغة 500,000 حرف شهريًا، بشرط التأكد من استهلاك الحساب الحالي قبل الدفعة. يبقى السقف الصلب المحلي 450,000 حرف للعملية الواحدة، مع سجل شهري اختياري يوقف التشغيل قبل تجاوز الحصة.

## تسلسل الإطلاق

1. يولد Workflow `generate-fahed-pilot.yml` عيّنة رسمية من المقاطع الأصعب في مقال الشاشة اللمسية، ثم يثبت MP3 وبياناته في الفرع.
2. يستمع المالك إلى الملف كاملًا. أداة الاعتماد تتطلب عبارة إقرار صريحة، وتتحقق من الصوت والهاش والمدة قبل فتح البوابة.
3. يولد Workflow `generate-fahed-full-pilot.yml` المقال كاملًا ويثبت أجزاؤه ذريًا.
4. بعد اعتماد المقال الكامل، تُنفذ الدفعة الباقية بنفس البصمة الصوتية، مع إعادة الاستخدام والاستكمال ومنع الاستبدال الجزئي.
5. يبقى صوت Hamed/Cedar المجمع رجوعًا فوريًا، ويبقى Gemini ترقية منفصلة لا حاجزًا للإطلاق.

## أوامر التشغيل والتحقق

```bash
npm run review:speech:fahed
npm run test:audio:fahed
npm run plan:audio:fahed
npm run build
```

توليد العيّنة الرسمية (في بيئة الأسرار فقط):

```bash
AZURE_SPEECH_KEY=... npm run generate:audio:fahed:pilot
```

لا توضع قيمة المفتاح في مستودع Git أو سجلات التنفيذ.

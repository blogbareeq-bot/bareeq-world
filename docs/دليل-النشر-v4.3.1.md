# دليل نشر عالم بريق V4.3.1

## محتوى الحزمة

الحزمة كاملة وتضم المصدر والأصول والوظائف والاختبارات وملف القفل. لا تضم `.git` أو `node_modules` أو `dist` أو مجلدات التخزين المؤقت؛ ينشئ Cloudflare ناتج `dist` بنفسه.

## الرفع الآمن

1. فك ضغط الحزمة في مجلد مستقل.
2. خذ نسخة احتياطية من مجلد المستودع الحالي.
3. احتفظ بمجلد `.git` الموجود في جذر `bareeq-world` ولا تحذفه أو تستبدله.
4. انسخ **محتويات** المجلد الداخلي للحزمة إلى جذر المستودع، واختر استبدال الملفات المتطابقة.
5. تأكد في GitHub Desktop من ظهور الملفات الجديدة والمعدلة، ولا تضف `node_modules` أو `dist`.
6. استخدم رسالة Commit: `Release Bareeq V4.3.1 with balanced footer`.
7. اختر **Commit to main** ثم **Push origin**.

## إعداد Cloudflare Pages

| الحقل | القيمة |
|---|---|
| Production branch | `main` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | فارغ |
| Node.js | 22 |

## التحقق بعد النشر

1. افتح **Workers & Pages > bareeq-world > Deployments**.
2. تأكد أن أحدث Commit هو V4.3.1 وأن حالته **Success**.
3. افتح `https://bareeqworld.com/` في نافذة خاصة مع تحديث قوي.
4. افحص التذييل على سطح المكتب: ثلاثة أقسام متقاربة، وروابط مهمة موزعة على ثلاثة أعمدة في الشاشة الواسعة.
5. افحص الجوال: التذييل أحادي العمود، ومجموعتا «روابط مهمة» و«تواصل معنا» قابلتان للفتح والإغلاق.
6. وافق على القياس واقرأ مقالًا إلى 75%، ثم تحقق من الحدث `article_read_75` في GA4.
7. افحص `sitemap.xml` و`robots.txt` و`rss.xml`.

## في حال فشل البناء

افتح سجل البناء وابحث عن أول سطر يبدأ بـ`Error:`. الحزمة اختُبرت من تثبيت نظيف؛ أكثر سبب متوقع بعد الرفع هو عدم نسخ جميع محتويات الحزمة إلى جذر المستودع. لا تنسخ المجلد الخارجي نفسه، ولا ترفع ZIP داخل المستودع.
